# Offline multimodal conformance (runtime)

This runtime ships the offline multimodal **conformance** path only. The
JEV-MM-15 fixture set (modalities, domains, scenario classes, and splits) was
generated by the separate training environment and is **not shipped** with this
release; the `jev_laya_free.trainer` module does not exist in this repository.
Nothing in this runtime produces a learned-model quality claim.

## What is shipped

* **Probe-gated modality manifest** (`jev_laya_free.multimodal.probe`): local
  observations only — a modality is `verified` only when the local probe
  exercised it against the live endpoint and observed a successful decode;
  `unavailable` means the probe observed a hard rejection; `not_verified` means
  no local probe ran. Upstream claims never count as local support.
* **Fail-closed adapters:** `prepare_video` and `prepare_audio` return
  `unavailable` (`video_not_verified` / `audio_not_verified`) without decoding
  when the probe has not verified the modality. Unknown modalities fail closed
  with a stable 503 — never a fallback to text.
* **Offline benchmark smoke** (`scripts/benchmark.py --backend offline`): the
  committed 12-capability fixture is exercised with no model, service, or
  network. It reports schema validity, deterministic guard behavior, and
  fail-open semantics — conformance evidence only.

```bash
PYTHONPATH=src python scripts/benchmark.py --backend offline --fixture fixtures/benchmark-smoke.jsonl
```

The probe and adapter behavior are covered by the runtime test suite
(`tests/test_probe.py`, `tests/test_media.py`, `tests/test_audio.py`,
`tests/test_video.py`, `tests/test_mm14_integration.py`).

## Provenance boundaries

* **No quality claim.** A capability claim requires held-out support that
  passes the acceptance gates in the separate training environment, and a gate
  passes only when the modality is verified by the local probe (never by
  endpoint presence alone), the split has sufficient support, and the
  deterministic policy's metric clears the threshold.
* **No fixture regeneration in-repo.** The JEV-MM-15 fixture set (600 examples
  at the default 5 variants, split into train/validation/test/calibration with
  `check_multimodal_leakage` and `calibration_gate`) is regenerated by the
  training environment's `multimodal-benchmark` command. This runtime does not
  regenerate it and does not ship the split files.
* **Determinism.** The shipped offline smoke is a pure function of the committed
  fixture; the fixture SHA-256 and environment metadata are recorded in the
  report.
* **Raw vs calibrated metrics** from the training environment are never
  conflated: the calibrated block (post-hoc temperature rescaling) is computed
  from a rescaled copy and is labeled as post-hoc test calibration, not raw
  held-out quality. This runtime does not compute either.
